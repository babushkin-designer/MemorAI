## Direction findings (options, not defects)

- **Retrieval surface is the missing half of the product.** README line 5
  promises data "ready for AI-powered retrieval", but the only read path is
  the crude `memorai` CLI — there is no search across `index.jsonl`, OCR
  text, clipboard, or transcripts. The maintainer already runs a local MCP
  server project (workspace-mcp) for agent search over Notion/GitLab; a
  `memorai search <query>` subcommand (grep/SQLite-FTS over index.jsonl +
  clipboard.jsonl + transcripts) or a thin MCP server over the same data is
  the obvious adjacent possible. Effort: M for CLI search, L for MCP server
  (coarse). Trade-off: SQLite index adds a write path to keep consistent.
- **Finish the retention story.** `tools/retention.sh` is written but nothing
  runs it; a LaunchAgent plist + `memorai retention` subcommand would complete
  it (pairs with finding 8). Effort: S.

## Findings considered and rejected

- ScreenMemoryManager thread-safety (finding 9): worst case is one missed or
  duplicate screenshot; a fix (serial queue for counters) is easy but pure
  churn against zero observed harm. Re-open only if capture logic grows.
- "Honoring `https_proxy`-style" false positives: none — the app makes exactly
  one network call (whisper model download from HuggingFace over HTTPS,
  `Transcriber.swift:283`), which is by design.
- Default output dir `~/Downloads/MemorAI` for sensitive data: arguably too
  exposed (any app with Downloads access can read it), but it is a deliberate,
  documented choice and user-configurable — flagged here, not planned.
  Consider `~/Library/Application Support` as default in a future major
  version. **2026-08-07:** sidestepped in practice — this machine's
  `outputPath` now points at `~/Documents/MemorAI` (Downloads was too easy to
  wipe by accident); the code default is unchanged.
